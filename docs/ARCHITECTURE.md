# Архитектура

## Границы компонентов

Backend — модульный Django-монолит. Доменные модели собраны в одном Django app
`library`, а авторизация, файлы, обработка, библиотека, чтение и настройки разделены
по модулям. Это сокращает служебные зависимости миграций для первоначального
масштаба около 50 пользователей. Frontend и backend находятся в одном репозитории.

React взаимодействует только с `/api/v1`. Все идентификаторы владельцев выводятся
из проверенной сессии. Обложки и PDF не имеют открытого `/media` URL.
Разрешения проверяются также для вложенных объектов, экспорта и Range.

PostgreSQL — источник истины; Redis — очередь и общий throttle. Celery обрабатывает
DB-очередь `ProcessingJob`. Периодическая сверка позволяет восстановить задания
после перезапуска. Файлы — в отдельном persistent volume с непрозрачными ключами.

## Загрузка

UploadSession резервирует объём с запасом для временных копий и обработки. Чанки
проверяются по размеру и SHA-256; повтор тех же байтов идемпотентен. Финализация
собирает исходный PDF, повторно проверяет его и создаёт фоновую задачу.
Один файл ограничен 100 000 000 байт. Количество книг тарифом не ограничено.
Реальная нехватка диска останавливает новые загрузки с явной ошибкой.

Истёкшие технические загрузки очищаются отдельно от корзины. Пользовательские
книги автоматически не удаляются. На слабом соединении браузеру после закрытия
может понадобиться повторно предоставить исходный файл для возобновления.

## Песочница

Доверенный worker передаёт один входной файл в spool. Отдельный контейнер без
сети, БД, Redis, секретов и основной библиотеки запускает PDFium в bubblewrap.
У parser отдельное пространство процессов и файлов, read-only вход, временный
каталог, ограничения CPU/RAM/размера результата. Docker socket не передаётся.

Worker принимает результат только после завершения parser namespace. Выходные
файлы открываются с проверкой типа, inode, размера и запретом symlink. Существование
`result.json` само по себе не считается завершением задачи.

Windows/local subprocess не обеспечивает эти Linux-границы и используется только
для разработки. В production нет автоматического перехода к менее защищённому режиму.

## Читалка

PDF.js получает авторизованные диапазоны через transport с обновлением access token.
Видимые страницы состоят из canvas, text layer и слоя аннотаций. Прочие страницы
представлены лёгкими placeholders; одновременно активен небольшой соседний диапазон.
Canvas ограничиваются пикселями и DPR. WebGL загружается лениво для перелистывания.

Выделения привязаны к неизменяемому BookFile: номер страницы, PDF-координаты,
цитата, prefix/suffix. Замена байтов существующего BookFile через API не поддерживается.
Во время изгиба используется временная текстура; выделение возвращается после него.
Вертикальный режим доступен всегда. Увеличенную страницу можно перемещать, а листать
кнопками. Уменьшение движения отключает пространственную анимацию.

Прогресс записывается в IndexedDB и отправляется с revision/client_mutation_id.
409 не разрешается выбором максимальной страницы: пользователь выбирает локальную
либо серверную позицию. Событие закрытия WebView не гарантировано; последняя
неподтверждённая операция повторяется при восстановлении. При выходе локальная
очередь очищается. Полноценное offline-хранение всей библиотеки не заявляется.

## Пароли и приватность

Сервер хранит исходный зашифрованный документ. Пароль передаётся непосредственно
PDF.js на устройстве и не сохраняется сервером или в пользовательских пресетах.
Для такого файла доступна стандартная или пользовательская обложка.

Приватность обеспечивает изоляцию пользователей и ограничения штатного Admin.
Это не end-to-end encryption: администратор инфраструктуры технически может читать
обычные файлы сервера. Авторизованному получателю нельзя запретить сохранить
уже выданные байты. Резервные копии шифруются отдельно.

## Дизайн

Базовый референс — example.jpg. Палитры и semantic tokens находятся в
`frontend/src/shared/themes.ts`, размеры/движение — в CSS variables. Градиентов нет.
Golos Text и Unbounded поставляются локально через @fontsource с OFL.
Библиотека не содержит вымышленных книг, демонстрационной статистики или production-моков.

## Расширение

Storage keys отделены от публичных URL, что позволяет добавить S3 adapter.
Обработчик выносится на отдельный узел вместе с передачей job-артефактов; текущий
локальный spool сам по себе не является распределённой файловой системой.
OCR и платежи не реализованы; добавляются отдельными доменами, не меняя ownership.
