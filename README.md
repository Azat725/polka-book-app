# Полка

Приватная PDF-библиотека в Telegram: Django REST API, React/TypeScript, PDF.js,
PostgreSQL и Docker Compose. Интерфейс основан на `example.jpg`: синий,
бордовый, кремовый и зелёный, без градиентов.

## Возможности

- Проверка Telegram initData на сервере, короткие bearer-сессии и ротация refresh.
- PDF до **100 000 000 байт**, передача частями, повтор и возобновление загрузки.
- Приватные PDF и обложки, авторизованные HTTP Range-запросы.
- Библиотека, папки, несколько коллекций, избранное и статусы чтения.
- Настоящие canvas и текстовый слой PDF.js: поиск, выделение, zoom, поворот.
- Вертикальное чтение и дополнительный режим перелистывания с изгибом WebGL.
- Прогресс и настройки каждой книги с локальной очередью и обработкой конфликтов.
- Закладки, цветные выделения, заметки, экспорт Markdown/JSON.
- Предупреждение и локальный ввод пароля зашифрованного PDF. Пароль не сохраняется.
- Десять тем, светлый/тёмный режимы, свои цвета и пресеты, текстуры и полки, RU/EN.
- Onboarding, профиль, статистика активности, корзина с ручным удалением.
- Django Admin, аудит, фоновая обработка, production-конфигурация и backup-скрипты.

## Локальный запуск на Windows

Нужны Python 3.13/3.14 и Node.js 24 LTS. В этой рабочей среде установлен Python 3.14.
Команды выполняются из корня проекта:

```powershell
py -3.14 -m venv backend/.venv
backend/.venv/Scripts/python.exe -m pip install -r backend/requirements-dev.txt
npm --prefix frontend ci
```

Если `.venv` уже существует, повторно создавать её не нужно.

Задайте `TELEGRAM_BOT_TOKEN` своего бота в окружении либо создайте приватный `.env`:

```powershell
python scripts/configure.py
python scripts/dev.py
```

Генератор запросит настоящий токен скрытым вводом и не перезапишет существующий `.env`.
Скрипт запускает миграции, Django, локальный обработчик и Vite.

- Интерфейс: http://127.0.0.1:5173
- Admin: http://127.0.0.1:8000/admin/
- Остановка сервисов: `Ctrl+C` в окне запуска.

Обычный браузер без Telegram показывает экран входа. **Обхода авторизации нет.**
Для интерактивной проверки в Telegram нужен HTTPS-адрес разработки, направленный
на frontend вместе с `/api`; настройте свой dev-домен или выбранный вами туннель.
Не направляйте Telegram на `127.0.0.1` телефона.

На Linux/macOS используйте `python3.13 -m venv backend/.venv` и
`backend/.venv/bin/python` вместо Windows-путей.

## Администратор

```powershell
backend/.venv/Scripts/python.exe backend/manage.py createsuperuser
backend/.venv/Scripts/python.exe backend/manage.py bootstrap_admin_roles
```

Команда спрашивает данные интерактивно. Начального общего пароля нет.
В production суперпользователь создаётся командой из руководства развёртывания.

## Проверки

```powershell
cd backend
.venv/Scripts/python.exe -m pytest
cd ../frontend
npm run lint
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

Полный E2E поднимает отдельные реальные backend, storage и обработчик; использует
временные ключи и изолированную тестовую БД. Пользовательская библиотека не затрагивается.

## Важные границы

Скан без текстового слоя читается, но OCR не включён. Сервер не расшифровывает
парольные PDF, поэтому их автоматическая обложка и число страниц могут быть
недоступны до открытия на устройстве. WebGL-эффект использует временное изображение
страницы только во время перехода; неподвижная страница имеет живой текстовый слой.

Локальный обработчик Windows — режим разработки. Production должен использовать
изолированный Linux sandbox без сети и секретов. Docker/HTTPS и настоящие мобильные
Telegram-клиенты требуют отдельной проверки перед публичным запуском.
